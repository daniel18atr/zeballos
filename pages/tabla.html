Glosario

Feedback Retroalimentación o comentarios que se dan sobre un producto o trabajo, para mejorarlo o ajustar su funcionamiento.
Software Conjunto de programas, aplicaciones y sistemas que hacen funcionar una computadora o dispositivo electrónico.
Hardware Componentes físicos de un sistema informático, como el monitor, el teclado, el disco duro o el procesador.
Bugs Errores o fallos en un programa que provocan comportamientos inesperados o incorrectos.
Stakeholders Personas o grupos interesados o afectados por un proyecto (clientes, usuarios, desarrolladores, empresa, etc.).
Algoritmo Conjunto de pasos lógicos y ordenados que permiten resolver un problema o realizar una tarea específica.
Interfaz Punto de interacción entre el usuario y el sistema. Puede ser visual (pantallas, botones) o técnica (entre programas).
Depuración Proceso de identificar y corregir errores (bugs) en un programa informático.
Iteración Repetición de un ciclo de trabajo en el desarrollo de software, donde cada vuelta mejora la versión anterior.
Sprint Ciclo de trabajo de duración fija (generalmente 2-4 semanas) en Scrum, al final del cual se entrega un incremento funcional del producto.
Backlog Lista priorizada de tareas, requisitos o funcionalidades pendientes de implementar en un proyecto de software.
Refactorización Proceso de reestructurar el código existente sin cambiar su comportamiento externo, mejorando su legibilidad, estructura y mantenibilidad.
Rollback Proceso de revertir un sistema a una versión anterior estable cuando un despliegue o actualización causa problemas en producción.
Escalabilidad Capacidad de un sistema o aplicación para aumentar su rendimiento o tamaño sin perder eficiencia.
Deployment (Despliegue) Proceso de poner el software en un entorno específico (pruebas, producción) para que esté disponible y operativo para los usuarios.
Pipeline Secuencia automatizada de etapas (compilación, pruebas, análisis, despliegue) que procesa el código desde el commit hasta su entrega en producción.
